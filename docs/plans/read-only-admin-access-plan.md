# 普通用户后台只读访问改造计划

> 状态：已验证（归档候选）
>
> 统一优先级：维护项
>
> 估算完成度：约 95%
>
> 最后核验：2026-08-29
>
> 剩余验收：普通用户/管理员真实浏览器权限矩阵。

## 1. 目标

将当前“管理后台仅管理员可进入”调整为：

- 所有已登录用户都可进入后台，浏览总览、知识库、系统提示词、Skill 和 MCP 模块。
- 普通用户可以查看列表和详情，但不能新增、上传、编辑、启停或删除共享资源。
- 管理员保留现有完整管理能力。
- 未登录用户仍不可进入后台或调用后台接口。
- Agent 管理继续不出现在后台导航中；本次不将它开放给普通用户。

方案使用“前端隐藏写操作 + 后端强制鉴权”的双层控制，复用现有 JWT、get_current_user 与 get_admin_user，不引入新的 RBAC 框架或数据库迁移。

## 2. 当前问题

当前 AdminApp 会在 user.is_admin 为假时直接显示“仅管理员可访问”；主导航也只给管理员显示管理后台入口。后端的知识库、系统提示词、Skill、MCP 读取接口多数同样要求 get_admin_user，因此只移除前端拦截仍会得到 403。

| 模块 | 普通用户目标 | 当前差距 | 改造方向 |
| --- | --- | --- | --- |
| 总览 | 查看运行概况与模块统计 | 依赖的读取接口仅管理员可用 | 对已登录用户开放所需 GET |
| 知识库 | 看列表与条目详情 | 列表/详情也要求管理员 | GET 改用当前登录用户；写操作不变 |
| 系统提示词 | 查看当前内容 | GET 也要求管理员 | GET 改用当前登录用户；保存不变 |
| Skill | 看列表、文件树与文件内容 | 读取要求管理员，页面有上传/启停/删除 | 只读 GET 开放，写操作保持管理员 |
| MCP | 看非敏感连接详情 | 读取要求管理员，配置可能含秘密 | 只读 GET 开放并脱敏 |
| Agent | 不在普通用户后台显示 | 旧页面/接口可能仍存在 | 保持导航隐藏、接口管理员专用 |

## 3. 权限模型

| 访问者 | 后台页面 | 模块列表/详情 | 写操作 | MCP 敏感配置 |
| --- | --- | --- | --- | --- |
| 未登录用户 | 不可进入 | 401 | 401 | 不返回 |
| 普通登录用户 | 可进入，只读标识 | 200 | 403 | 仅返回脱敏展示值 |
| 管理员 | 可进入 | 200 | 按现有逻辑允许 | 返回编辑所需完整配置 |

规则如下：

- 读取共享后台资源依赖 get_current_user，仅验证已登录。
- 任何改变共享资源的操作继续依赖 get_admin_user；不能只依赖前端隐藏按钮。
- Agent 相关接口继续保持管理员权限，因为它不属于本次只读开放范围。
- 普通用户绝不能通过 MCP 详情接口读取 headers、环境变量、Token、密码或其他凭据的明文。

## 4. 后端最小改造

### 4.1 调整只读路由

修改以下现有路由的依赖，不改变其业务数据和返回主体：

- app/api/knowledge.py
  - 知识库列表与单条详情 GET：get_admin_user 改为 get_current_user。
  - 新建、更新、删除：继续使用 get_admin_user。
- app/api/system_prompt.py
  - 当前系统提示词 GET：改为 get_current_user。
  - 更新提示词 PUT：继续使用 get_admin_user。
- app/api/sandbox.py
  - Skill 列表、详情、文件树、文件内容等纯读取路由：改为 get_current_user。
  - MCP 列表和详情等纯读取路由：改为 get_current_user。
  - Skill 上传、启停、删除；MCP 新增、更新、删除；Agent 的读写接口：继续保持管理员限制。

### 4.2 MCP 响应脱敏

在 app/api/sandbox.py 或对应响应模型中新增统一的 MCP 展示映射：

- 管理员读取时保持当前返回结构，避免破坏既有编辑页。
- 普通用户读取时，对 headers、环境变量及其他机密字段替换为 *** 或“已配置”，原值不得进入响应、日志或前端状态。
- 普通用户仍能看到名称、描述、启用状态、服务类型、参数键名和“是否已配置”等查看所需元数据。
- 前端对脱敏字段显示“已配置（仅管理员可查看）”，避免用户将掩码误认为可编辑内容。

若当前 MCP GET 没有独立详情模型，应优先增加轻量 DTO 或序列化函数，不在前端临时删除敏感字段。

### 4.3 错误约定

- 无 JWT 或 JWT 失效：保持 401。
- 普通用户调用写接口：保持 403，并返回明确但不暴露内部细节的提示。
- 前端收到 401 时引导重新登录；收到 403 时提示“此账号仅有查看权限”。

## 5. 前端最小改造

### 5.1 入口和统一只读状态

修改以下文件：

- frontend/src/components/layout/Header.tsx
  - 对所有已登录用户显示“管理后台”入口，而不再仅显示给 is_admin 用户。
- frontend/src/admin/AdminApp.tsx
  - 页面门槛改为“未登录不可进入”。
  - 计算 readOnly = !user.is_admin，并向各后台页传递，或通过轻量 Hook/Context 提供。
  - 普通用户进入时显示固定“只读访问”说明。
  - 不将 AgentsPage 加入左侧导航。

### 5.2 页面呈现

| 页面 | 普通用户可见 | 普通用户隐藏或禁用 |
| --- | --- | --- |
| 总览 | 所有已有统计和状态 | 无写操作 |
| 知识库 | 列表、搜索、条目详情 | 新建、编辑、删除及确认弹窗 |
| 系统提示词 | 当前内容和只读说明 | 保存与编辑态输入控件 |
| Skill | 列表、描述、状态、文件树/内容详情 | 上传 ZIP、启用/停用、删除 |
| MCP | 列表、非敏感配置详情、状态 | 新建、编辑、删除、敏感值明文 |

详情组件应支持 readOnly 模式，避免复制一套普通用户页面。系统提示词在只读模式可以使用文本/Markdown 展示，或使用真正的 readOnly 输入控件，避免出现“可以输入但不能保存”的假操作。

预计涉及文件：

- frontend/src/admin/AdminApp.tsx
- frontend/src/components/layout/Header.tsx
- frontend/src/admin/pages/KnowledgePage.tsx
- frontend/src/admin/pages/PromptPage.tsx
- frontend/src/admin/pages/SkillsPage.tsx
- frontend/src/admin/pages/McpsPage.tsx
- 视实际类型需要调整 frontend/src/api/admin.ts 与 frontend/src/admin/types.ts

## 6. 实施顺序

1. 记录当前管理员后台行为，梳理每个读写接口及调用方。
2. 先改后端读取权限与 MCP 脱敏，补充权限矩阵测试。
3. 修改后台入口、AdminApp 登录门槛与只读状态传递。
4. 逐页隐藏写操作，保留列表、搜索和详情；确认 Agent 管理未暴露。
5. 运行前端 lint/build，重启主服务并更新 frontend/dist。
6. 用管理员与普通账号完成真实浏览器/API 验收，清理验收新增的共享资源。

## 7. 验证计划

### 7.1 后端权限回归

- 未登录请求知识库、提示词、Skill、MCP 的读取接口均返回 401。
- 普通用户请求上述读取接口均返回 200。
- 普通用户请求知识库增删改、提示词更新、Skill 上传/启停/删除、MCP 增删改均返回 403。
- 管理员原有读写流程仍成功。
- 普通用户读取 MCP 时，响应不含真实凭据；管理员响应仍满足编辑页需要。

### 7.2 前端验收

普通用户：

1. 登录后能从主导航进入管理后台。
2. 能切换总览、知识库、系统提示词、Skill、MCP，并查看列表和详情。
3. 页面中不出现上传、保存、新建、编辑、启停、删除及相应确认操作。
4. MCP 敏感配置仅显示掩码或“已配置”状态。
5. 通过浏览器开发者工具直接调用写接口，仍返回 403。

管理员：

1. 原有入口、页面和所有写操作仍可用。
2. Skill 上传/启停/删除、知识库维护、提示词保存、MCP 维护不回归。
3. Agent 管理继续维持当前“不在导航暴露”的产品决定。

### 7.3 质量门禁

执行现有后端回归、前端 lint 与前端 build。前端构建完成后，按项目启动方式重启主服务，确认 FastAPI 提供的是新的 frontend/dist，再进行真实页面验收。

## 8. 验收标准

- 普通登录用户可浏览约定模块的列表和详情，不再被“仅管理员可访问”页面阻断。
- 普通用户在 UI 和 API 两层均不能修改共享知识库、提示词、Skill、MCP 或 Agent 配置。
- 管理员能力不回归。
- MCP 等敏感配置不会因开放只读接口而泄露。
- 不新增角色表、权限迁移、独立后台或重复页面；改动聚焦于现有认证依赖、响应脱敏和后台 UI 权限态。

## 9. 范围外事项

- 普通用户向共享知识库或共享 Skill 目录上传内容的审批流程。
- 用户、角色、组织、审计日志等完整 RBAC/多租户体系。
- 普通用户管理或调用后台 Agent 配置。
- 改变普通用户在对话页上传个人分析文件的能力；该能力与上传共享知识库/Skill 必须保持明确区分。
